# APP_SPEC 追補 — トリガー駆動ブロック引き戻し (TRIGGER_V3, 2026-06-13)

本追補は APP_SPEC.md の §3「ターンパイプライン」§4「設定値」§表2「ロードする成果物」に
対する更新。検証根拠は `trigger_experiment/RESULTS.md`(全数値ファイル直読検証済み)。

## 背景 — 何を直したか

旧 `attn_trigger4_head`(SP 参照検知トリガー)は AUC 0.830 で v1 では OFF、ブロック
引き戻し(`block_recall.py`)は毎ターン無条件 retrieve だった。この追補は引き戻しを
「**必要なターンだけ**」発火させる学習済みゲートを導入する。

## 成果物(追加)

| 成果物 | パス | 用途 |
|---|---|---|
| recall トリガーヘッド | `trigger_experiment/results_v3/trigger_head_v3_gate.npz` | 4608dim ロジスティック+閾値。「このターンは evicted 事実が要るか」を判定 |
| ランタイムゲート | `trigger_experiment/trigger_gate.py` | 本番レイアウト [BOS][SP][窓][質問] で質問位置 pre-RoPE クエリ(層8/14/20)を採り、上記ヘッドでスコア |

## ゲートの作り方(学習・本体SFTなし)

1. ラベル: フル KV で回答を teacher-forcing し、回答位置のアテンション質量が露出窓より
   前(evicted 領域)へ飛ぶか否か(BOS シンク除外)。「飛んだ=引き戻しが必要だった」を
   正解ラベルとする。これは推論時には観測できない、訓練時のみ得られる本物の教師信号。
2. 生徒特徴: 本番と同じ [BOS][SP(pooler)][露出窓512][質問] で採った質問位置 pre-RoPE
   クエリ(Phase B と同形。フル KV 文脈で採ると V3 既知のドリフトで本番とズレる)。
3. ヘッド: 4608次元ロジスティック回帰。会話単位 GroupKFold、未知テンプレ評価。
   GPU はラベル・特徴採取のみ(数分)、訓練は CPU 数秒。

## §3 パイプラインへの差し込み(8. 生成 の内側)

`app_session_torch.AppSession`、環境変数 `SPCHAT_TRIGGER=head` で ON(未設定=従来の
毎ターン無条件 retrieve、完全後方互換):

```
    SPCHAT_TRIGGER=head:
      gate.fires(kept, window, user_msg) が False → retrieve をスキップ
      True → 従来どおり top-k を [SP] と [露出窓] の間に逐語再注入
```

## 実測(本番20問×2アーム、`results_v3/gated_*`)

| 質問種別 | always(従来) | gated(本追補) |
|---|---|---|
| evicted 事実の想起 10問 | 正答8/10・発火10/10 | 正答7/10・**発火10/10** |
| 窓内事実 4問 | 2/4・発火4/4 | 2/4・**発火1/4** |
| 雑談 6問 | 6/6・発火6/6 | 6/6・**発火1/6** |

- evicted 想起ターンは **10/10 発火**(取りこぼしゼロ)。正答 8→7 の差1問は発火した上での
  生成ゆらぎ(ゲートのスコア探査が RNG を進める)で引き戻し漏れではない。
- 陰性10問中 **8問をスキップ**。引き戻し回数 20→12(全体40%減、陰性に限れば80%減)。
- 誤発火2問はいずれも閾値 -2.6 のすぐ上。誤発火コストは「余分に1回引く」=従来の毎ターン
  挙動と同じで正答性に無害。無駄打ちを更に減らすなら閾値 -2.0(ラベル保存済み・再調整GPU不要)。
