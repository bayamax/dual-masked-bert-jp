# TRIGGER_V1 結果 (2026-06-13)

リコールトリガー実験第一段: 「フルKV教師のアテンションが露出窓(512tok)より前の
evicted領域に飛ぶか」を質問種別に計測し、生徒特徴(質問位置pre-RoPEクエリ、
Phase Bと同一採取)からそれを予測するヘッドを訓練した。

実行: RunPod A6000、TRIGGER_POD_V1、00:21–00:47 UTC(26分)、実費 $0.156。
数値は回収した npz からローカル再計算で検証済み(ログ転記ではない)。

## 前提検証(教師アテンションの行き先、BOSシンク除外、n=1200 train / 360 heldout)

evicted質量比の中央値(train、層 8/14/20 = L0/L1/L2):

| 質問種別 | L0 | L1 | L2 |
|---|---|---|---|
| EVICT(窓外needle想起) | .371 | **.490** | .413 |
| WINDOW(窓内needle想起・ハード陰性) | .181 | .130 | .118 |
| GENERIC(過去参照なし) | .266 | .236 | .127 |

- EVICT p10 (L1=.439) > WINDOW p90 (L1=.151): **分布が完全分離**。
  測定値そのものの ORACLE AUC = 1.0000(evict-vs-rest / evict-vs-window とも)。
- 「必要なときだけ窓外にアテンションが飛ぶ」という前提は合成バッテリー上で成立。
- GENERIC でも .13–.27 の拡散質量が窓外に飛ぶ(長文履歴への背景アテンション)
  ため、生の質量に固定閾値を切るなら層と閾値の選択が要る(L1 が最も分離)。

## トリガーヘッド(ロジスティック回帰 4608dim、C=0.003、GroupKFold by seed)

評価は未知シード+未知テンプレ(heldout 5種、n=360):

- EVAL AUC evict-vs-all: **1.0000**
- EVAL AUC evict-vs-window(本丸): **1.0000**
- EVAL AUC evict-vs-generic: **1.0000**

既存 attn_trigger4(AUC 0.830、v1 で OFF)に対し、ラベルをフルKV実アテンションに

## 注意(まだ言えないこと)

1. **合成テンプレ域での天井**であり、実会話・実 web 混在ターンへの汎化は未測。
   composite 系バッテリーでの実戦評価が次。

# 配線テスト + recall-query 最終 (2026-06-13)

## gated 受け入れテスト(実機、本番20問×2アーム) — results_v3/gated_*
SPCHAT_TRIGGER=head をアプリに配線し「毎ターン引く(always)」vs「発火時のみ(gated)」を実測。
- evict needle 10問: **ゲート発火 10/10**(窓外の事実が要るターンを一つも見逃さない)。
  想起 always 8/10 → gated 7/10。差の1問は発火した上でのMISS(スコア探査の余分な
  forwardでRNGがずれた生成ゆらぎ、引き戻し漏れではない)。
- 陰性(窓内+雑談)10問: **8/10を正しくスキップ**。誤発火2問はどちらも閾値-2.6の
  すぐ上(snack -2.25 / package -2.17)、閾値を-2.0にすれば誤発火ゼロ。
- 引き戻し回数: **20 → 12(全体40%減、陰性に限れば80%減)**、想起精度は維持。
- 結論: 過去参照ターンだけ正確に発火し、無駄な引き戻しを大幅削減。学習不要・配線のみで実装済み。

## recall-query: 発火位置の隠れ表現をクエリにする案 — results_recallq/
同じ会話・キー・教師ラベルでクエリの採取位置だけ3通り。Phase Bインデクサで5シード平均
(未知テンプレ heldout top-2, n=180):
- q_fullq(質問位置・フルKV=Phase B現行)  : **0.876** sd.024 ← ただし本番では採れない上限
- q_spq  (質問位置・本番SP文脈)            : 0.826 sd.031 ← 本番で採れる
- q_spans(回答位置・本番SP文脈=新案)      : 0.840 sd.029 ← 本番で採れる
- 生qk(学習なし)では q_spans が最下位(0.35) — 回答位置は生だと最も情報が薄い。
- 結論: **回答位置クエリは質問位置と統計的に同等(1SD以内)で、改善にならない**。
  引き先は現行の質問位置 + BGEアンサンブル(.983)のままで良い。直感は正しいが、
  質問の隠れ表現に既に「過去の特定値を指す」情報が十分入っており、回答位置まで待つ
  上積みが無い、と解釈できる。

# CoTscan: アテンション定義の引き戻し位置 (2026-06-13) — results_cotscan/
ユーザー指摘の忠実版。生成なし。回答列の全トークン位置で各 evicted ブロックへの
アテンションを測り、単一の遠ブロックに最も集中する位置=引き戻し位置、そこで最大
アテンションを受けたブロック=gold(アテンションが飛んだ先)。A4000、~13分、$0.04。
heldout はテンプレ分離(train 23 / held 8 種)。npz からローカル再計算で検証済み。

## Q2 mid-CoT ゲート(前提)= 完全成立
- 引き戻し位置の gold ブロックへのアテンション 0.229 vs 非引き戻し位置 0.018(100% で前者が上)
- **アテンションが飛んだ先 == 植えた事実ブロック が 100%** — モデルは正しい場所に引き戻している
- SP 文脈の隠れ表現で引き戻し位置 vs 非引き戻し位置を分離 **AUC 1.000**
  → 「512前のアテンションが閾値超えた瞬間を、推論時の隠れ表現だけで検出できるか」= Yes

## Q1 想起(隠れ表現から gold を引けるか)
- 学習インデクサ: 引き戻し位置クエリ top-2 **1.000**(未知テンプレ)= **隠れ表現から正しい
  ブロックを引っ張り出せる**(ユーザー仮説の核心は成立)
- ただし生 qk では 0.350 で質問位置 0.762 に劣り、インデクサ後は両者とも 1.000 に飽和
  → 「引き戻し位置クエリが質問位置クエリより優れる」とは言えない(同等)。バッテリーが
    易しく差が潰れている可能性あり(生qkが識別シグナル)。

## 解釈
- **仕組みは end-to-end で動く**: 位置ごとにアテンション監視→引き戻し位置を検出(AUC 1.0)
  →その隠れ表現から正しいブロックを学習射影で復元(top-2 1.0)。ユーザー設計は妥当。
- 単問ベンチでは「引き戻し位置 > 質問位置」は出ない(同等)。だが本来の用途=長い CoT の
  途中で質問が値を名指さず段階的に複数事実が要る場面では、各ステップで使えるのは引き戻し
  位置クエリだけで、それが機能する(1.0)ことが要点。
