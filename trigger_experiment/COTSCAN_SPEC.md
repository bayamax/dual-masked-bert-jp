# 仕様追補 — CoT 途中の SP 圧縮事実リコール (COTSCAN_V1, 2026-06-13)

SP に圧縮されて露出窓から外れた具体事実を、**生成(CoT)の途中で、隠れ表現を手がかりに
引き戻せるか**を検証した結果と、それを本番に入れるための設計。APP_SPEC_ADDENDUM.md
(トリガー駆動ブロック引き戻し)の姉妹文書。検証根拠は GitHub ブランチ
`claude/huggingface-model-status-ypclnu` の `trigger_experiment/RESULTS.md`「CoTscan」節
および `trigger_experiment/results_cotscan/`(全数値ファイル直読検証済み)。

## 解こうとした問題

SP 圧縮は高エントロピーな具体値(価格・番号・寸法)で情報を失う。長い CoT の途中で
「その値が必要になった瞬間」に、露出窓より前(=evicted 領域)へ引き戻せれば、
圧縮で失った正確値を回復できる。問うべきは 2 つ:

- **Q2(前提)**: そもそも「引き戻しが必要な瞬間」を、推論時に観測できる隠れ表現だけで
  検出できるか。`SPCHAT_TRIGGER` ゲートをターン頭 1 回でなく **トークン位置ごと**に
  使えるか。
- **Q1(本題)**: その引き戻し位置の隠れ表現から、**正しい evicted ブロックを引っ張り
  出せるか**。

## 方法(生成不要・教師強制・アテンション定義)

1. 会話に具体事実を 1 つ植え、filler で押し出して evicted 領域に入れる。
2. 値を使う短い回答を教師強制し、**回答の全トークン位置で各 evicted ブロックへの
   アテンション質量を測定**(層 8/14/20、ヘッド和、BOS シンク除外、行正規化)。
3. 単一の遠ブロックにアテンションが最も集中する位置 = **引き戻し位置**(手書きでなく
   アテンションで定義)。そこで最大質量を受けたブロック = **gold**(=アテンションが
   実際に飛んだ先)。
4. 本番レイアウト `[BOS][SP(pooler)][露出窓512][回答]` で同じ位置の **pre-RoPE クエリ
   (隠れ表現)** を採取し、Phase B 同型インデクサで gold ブロック想起を学習・評価。
   heldout はテンプレ分離(train 23 種 / held 8 種)。

実行: A4000、約 13 分、$0.04。生成器 `cot_attn_scan_labels.py`、評価 `cot_recall_eval.py`、
ジョブ `run_cotscan.sh`(いずれも上記 GitHub ブランチ)。

## 結果

### Q2 mid-CoT ゲート = 完全成立
- 引き戻し位置の gold ブロックへのアテンション **0.229** vs 非引き戻し位置 **0.018**
  (100% のサンプルで前者が上)= 引き戻し瞬間に明確なスパイク。
- **アテンションが飛んだ先 == 植えた事実ブロック が 100%** = モデルは正しい場所に
  引き戻している(アテンションは「どのブロックか」の信頼できる教師)。
- SP 文脈の隠れ表現で引き戻し位置 vs 非引き戻し位置を分離 **AUC 1.000**
  → 「アテンションが閾値を超えた瞬間を、推論時の隠れ表現だけで検出できるか」= **Yes**。

### Q1 隠れ表現からの想起 = 成立
- 学習インデクサで引き戻し位置クエリの未知テンプレ top-2 = **1.000**
  → **隠れ表現から正しいブロックを引っ張り出せる**(本仮説の核心は成立)。
- ただし生 qk では 0.350 で質問位置 0.762 に劣り、学習後は両者とも 1.000 に飽和。
  → 「引き戻し位置クエリが質問位置クエリより**優れる**」とは言えない(**同等**)。
    単問バッテリーが易しく差が潰れている可能性(生 qk が識別シグナル)。

## 結論と適用範囲

- **仕組みは end-to-end で動く**: 位置ごとにアテンション監視 → 引き戻し位置を検出
  (AUC 1.0) → その隠れ表現から学習射影で正しいブロックを復元(top-2 1.0)。
- 単問では「引き戻し位置 > 質問位置」は出ない(同等)。**本来の用途**=長い CoT の途中で
  質問が値を名指さず、複数事実を段階的に要する場面では、各ステップで使えるのは引き戻し
  位置クエリだけで、それが機能することが要点。
- リコール先(どのブロックか)は現行 BGE / Phase B インデクサ(.983)で足り、本機構は
  「ターン頭 1 回」を「CoT 途中の各ステップ」に拡張する道筋を実証したもの。

## 本番化に向けた残作業

1. **per-position ゲートの配線**: 現行 `trigger_gate.py` はターン頭 1 回。生成ループ内で
   各ステップの隠れ表現にゲートを適用し、発火位置で mid-stream にブロックを再注入する
   配線(`app_session_torch._gen_once` の rebuild に mid-stream recall を追加)。
2. **実 CoT での検証**: 本検証は教師強制回答。実生成 CoT(R1 は長考)では発火位置が
   変わりうるので、生成ループ実装後に再検証。
3. MLX 本番への移植(`HANDOFF_PORTING.md` パリティ手順)。
