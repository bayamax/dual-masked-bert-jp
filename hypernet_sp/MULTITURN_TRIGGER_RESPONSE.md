# RESPONSE: マルチターン検索トリガー過発火(欠陥 #17)— 原因と再学習版

`MULTITURN_TRIGGER_REPORT.md` への回答。

## 判定: 仮説(SPスコープ)は方向として正しいが、真因はより広い「レイアウト分布シフト」

v3 トリガー(`attn_trigger3_head.npz`)の学習条件は `[BOS + SP(単一事実~30tok圧縮) + 質問]`。
本番は `[SP(distant全体の圧縮) + raw window + 質問]` で、SP の中身もattention の競合相手も
別分布。学習時 μ/σ での標準化が z-score を飽和させ、シグモイドが常時 ~1.0 に張り付く —
「12×3は?」=0.998 はこの数理であり、**閾値調整では直らない**。

実測の裏付け: 本番レイアウトでは平均 SP 質量が 0.039(v3 学習時は 0.53)と桁違いに小さく、
さらに**有効な「検索ヘッド」自体が総入れ替わった**(下記)。

## 対応: 本番レイアウトでの再学習(`attn_probe4.py` → `attn_trigger4_head.npz`)

データ構成: 多ターン会話プレフィクス(対象事実は distant 領域に配置、数値を含まない
filler ターンで嵩増し)→ kept を pooler で SP 化 → raw window → 参照型/自己完結型の質問。
ヘッド選択は fold 内再実行(選択リークなし)。

- **LOO-CV: AUC 0.830、pairwise 28/30**
- 選択ヘッド: **L11H7 / L11H9 / L11H10 / L15H1 / L15H4 / L16H5**(全 fold で安定 30/30)
  — v3 の L1/L7/L21/L22 系とは完全に別。レイアウトが変わると検索ヘッドも変わる
- 運用表(in-sample、閾値選定用):

| th | recall | 誤発火 |
|---|---|---|
| 0.4 | 23/30 (77%) | 6/30 (20%) |
| 0.5 | 21/30 (70%) | 6/30 (20%) |
| **0.6** | 20/30 (67%) | **3/30 (10%)** |
| 0.7 | 19/30 (63%) | 2/30 (7%) |

**推奨 th=0.6**。誤発火のコストが「不要な再注入1回」である一方、本番ではトリガーは
唯一の経路ではない(intent ルーティング+pin 注入が主経路で、トリガーは取りこぼしの
補完)ため、v3 推奨(0.35)より高めが正しい。

**正直な注記**: 本番レイアウトでの分離は AUC 0.83 — おもちゃ条件の 0.97 より本質的に
難しい(raw window が競合するため)。トリガーは「ソフトな補完信号」として扱い、
確定的な依存はしないこと。

## 質問への回答

1. **SP スコープ**: distant(kept バッファ)のみが正。会話全体を SP に入れる実装は誤り。
   また #16 により kept が空の間は SP 自体が存在しない — その間トリガーは評価不能なので
   **kept 非空のときだけスコアする**こと
2. **アーティファクト**: `attn_trigger4_head.npz`(numpy のみ、heads/coef/μ/σ/rw 同梱)を
   使用。v3(`attn_trigger3*`)は本番では使用しない(おもちゃレイアウト専用)
3. **閾値**: 上表。0.6 から開始し、計装ログ(発火率と「発火したのに注入が無関係だった」率)
   で現地調整
4. **照応解決の置き場所**: クエリ書き換え層(`anaphora.py`)であってトリガーではない。
   **finding B は修正済み**: 値照応 NP(the number/total/price/...)と金額・小数の
   エンティティ抽出を追加 — 「Can you verify the number?」→
   「Can you verify the number? **(Brent, $82.40)**」(15/15 テスト)

## ルーティング仕様(発火後)

```
trigger 発火 → まずメモリ階層から再注入(pins → L1 → L2)
            → Web は intent が lookup の場合のみ(expand_web_query を通す)
```
「文脈を思い出す必要がある」(トリガーの検知対象)と「世界知識が要る」(Web の出番)は
別の信号であり、トリガー→Web 直結が finding B の悪化要因でもあった。
