# ゼロベース再設計 — 調査結果と Phase A/B/C 計画 (2026-06-12)

発端: 「質問内容や用途によって分岐させるのはキリがない。本質は『露出窓のトークンで回し、
SP に入ったトークンを呼び出す』こと。何を保存し、どこから何を呼び出すかがキモ。
外付け regex や小分類器で足りないなら、何を学習させるべきかまで踏み込む」(オーナー)。

オーナー原案: **引き直しロジット増設&学習** — フル文脈の教師走行で、露出窓より前
(BOS と現在クエリを除く)へ注意質量が飛んだ瞬間を正解ラベルとして引き直しロジットを
活性化するよう学習。その時の隠れ表現を BGE 意味空間に変換する小モデルで対応チャンクを
引き戻す。

これを 5 方向の文献調査(training-free KV 検索 / 学習型スパース注意 / アクティブ RAG
トリガー / 外部メモリ機構 / オンデバイス実現性、計 ~190 ツール呼び出し、一次ソース裏取り付き)
と照合した結論と、その後の実装・実測を記録する。

## 1. 原案の照合結果(3 部品に分解)

| 部品 | 判定 | 根拠 |
|---|---|---|
| ① 教師注意質量からの蒸留でトリガー学習 | 実証済みの王道。そのまま採用 | DSA lightning indexer (arXiv:2512.02556): 教師注意を全ヘッド合算→L1 正規化→KL、本体凍結 2.1B tok。SeerAttention-R (arXiv:2506.08889): **DeepSeek-R1-Distill-Qwen-14B に凍結+0.4B tok+<20 GPU 時間で後付け成功**(同系列 1.5B への移植性ほぼ保証) |
| ② LM ヘッドへのロジット増設 | 形を変える: 分離プローブヘッドに | 増設ロジットの発表例ゼロ。語彙トークン方式 (Self-RAG) は 7B 未満の成功例なし。隠れ状態プローブは **Gemma-2B で実証** (Probing-RAG, arXiv:2410.13339) — ラベルは「検索で答えが変わったか」 |
| ③ 隠れ状態→BGE 空間変換で引き戻し | セッション内では不採用(KV 空間直接照合が勝つ)。外部ストア用に採用 | EM-LLM (arXiv:2407.09450): 自セッションの追い出しトークン想起で、モデル自身の Q/K 照合が SOTA 外部埋め込み RAG に **LongBench +30.5%** で勝利。逆方向の証拠なし。外部ストア用の隠れ状態→埋め込み射影は実証済み (ImpRAG arXiv:2506.02279 は 3B で動作; One Model Is Enough arXiv:2603.08429 は射影ヘッドで 97% 保持) |

原案の**未発表(=新規)部分**: (a) 「既に追い出した領域への引き戻し」として学習する框組み
(既刊セレクタは常駐ブロックの採点のみ; TRIM-KV arXiv:2512.03324 は学習 eviction だが引き戻しはない)、
(b) BOS シンク質量をラベルから除外する洗浄(既刊はシンクを残すか構造的にハードコード)。

## 2. 周辺の決定的実測(設計の支持材料)

- **SP/gist 圧縮は正確値で激しく劣化**: 4 倍圧縮で exact-recall 93.9%→40.6%、32 倍で 11.9%。
  意外性の高い情報ほど優先的に落ちる。ambient な文脈は near-lossless (arXiv:2412.17483)。
  → 「SP=雰囲気の継承、逐語ブロック=正確値の復元」の二層が文献的に正しい役割分担。
- **3GB 予算は成立**: Q4 重み 1.12GB + 8k 窓 q8 KV ~117MB + 埋め込みモデル <200MB ≈ 1.6-1.8GB。
  追い出し KV は q4 で ~8MB/1k tok → フラッシュ保存が現実的。KV 復元は再プリフィル比
  最大 136 倍の TTFT 短縮 (arXiv:2603.04428)。モバイル向けフラッシュ KV オフロードは
  KVSwap (arXiv:2511.11907) / DynaKV (arXiv:2511.07427) が既に存在。
- **冷や水 2 点**: ACL 2025 の 35 手法ベンチ (arXiv:2501.12835) は「凝った adaptive-RAG は
  単純な不確実性推定と同性能」— 学習トリガーは必ず単純ベースラインと比較する。
  training-free KV 検索の 1-3B 検証はほぼ皆無(最小 Phi-3 3.8B)— 自分で測るしかない。
- ルーティング論との接続: 既存 6 クラスの大半は「答えがどこに居るか」(read/write/compute/none
  + 読み出し元)の代理変数。引き戻しが確立すれば外付け分岐は最小限に畳める。

## 3. ロードマップ

- **Phase A(training-free、CPU、実装済み)**: 露出窓から出たトークンを 128-tok ブロックに
  封緘し、各ブロックの pre-RoPE キー(k_proj 出力、3 中間層)を保持。ターン毎に現在
  メッセージの pre-RoPE クエリで全ブロックを採点(GQA 折り畳み、ヘッド平均→キー max→
  クエリ平均、層加算)、top-k を SP と露出窓の間に**逐語再注入**。
  実装: `block_recall.py` (BLOCKRECALL_V1) + `app_session_torch.py` フラグ配線
  (`archive=None` で従来動作と完全一致)。検証: `needle_recall_test.py` — 同一履歴・同一
  質問で sp(現状)/qk(Phase A)/bge(同予算で BGE 照合)/full(フル KV 天井)を直接比較。
- **Phase B(学習、RunPod 単 GPU 数日)**: Phase A が小型ゆえ不足なら、原案=注意蒸留
  セレクタ。SeerAttention-R レシピ(凍結本体、0.1-0.4B tok、KL)+原案の差分(引き戻し框組み、
  シンク除外ラベル)。教師=フル KV 走行の注意質量(注: 教師ラベル生成時のレイアウト
  分布シフトに注意 — v4 トリガーの失敗要因)。
- **Phase C(外部ストア)**: 「いつ外に出るか」= Probing-RAG 型 FFN プローブ(ラベルは
  既存バッテリーから機械生成)。「何を探すか」= 隠れ状態→BGE 射影ヘッド(One Model Is
  Enough のアラインメント+対照+順位蒸留損失)。手書き照応 regex と v4 注意質量トリガーの
  両方を置き換える。正直さの保証(honest miss / 最近接提示 / オフライン拒否)は read パスの
  性質としてサーバー側に残す — モデルは「X が要る」と表明するだけ。

## 4.0 最終判定(2026-06-12、全数値ファイル直読検証済み)

**A方式(BGE引き戻し)を正式採用。** 根拠:

| 測定 | 結果 |
|---|---|
| ニードル(4213tok/10問) SPのみ | 0/10 |
| 同・**BGE引き戻し(採用)** | **7/10** |
| 同・QK生照合 | 1/10(退化、§4参照) |
| 同・**フルKV** | **1/10** ← 「天井」ではなかった |
| 回帰 v1(recall ON) | 12/12 |
| 回帰 v2(recall ON / OFF 対照) | 15/17 / 15/17 — **差分ゼロ**(C2/C3 は既知のseed依存天井) |

**最重要の発見**: 4千トークン級では、この 1.5B は全履歴が注意窓内にあっても文中の
正確値を拾えない(小型モデルの lost-in-the-middle; 745tok では 3/3 だった)。
関連ブロックだけを質問直前に再注入する引き戻しは 7/10 を維持 — つまり
**「露出窓+引き戻し」はフルKVの妥協ではなく、長文ではフルKVに勝つ構成**。
当初目標「フルKV同等以上」を超過達成。

残りギャップ(7→10)は検索ミス(goldブロックがtop-2に入らない)であり、
Phase B 学習インデクサの担当。Phase B v1 は同分布 val top-2 100% だが、
(a) 学習時クエリが回答位置で推論時と不一致だった設計ミスを修正(質問位置に変更)、
(b) 未知テンプレートの held-out 評価を追加して V2 を再学習(結果は §4.5 追記参照)。

## 4. Phase A 実測ログ(検証済みの数値のみ — §6 の注意を必ず読むこと)

ニードル想起ベンチ `needle_recall_test.py`(履歴 4213 tok、10 needles、ログ直読で検証):

| 条件 | 結果 | 備考 |
|---|---|---|
| sp(SPのみ・現状) | **0/10** | 正確値は全滅。値の言及があった事実だけ gist に残る — 文献の圧縮損失定量(arXiv:2412.17483)と整合 |
| qk(pre-RoPE 生 q·k 照合) | **1/10 — 退化** | スコアがクエリ非依存(全質問で top5 ブロックが同一)。唯一の的中はブロック 0 が gold だった偶然 |
| bge(同トークン予算・BGE cosine) | **7/10** | テキスト埋め込み検索は素直に機能 |
| full(フル KV 天井) | スモーク 3/3(745 tok)。4213 tok では fp32 注意スパイクで未完(要チャンクプリフィル) | |

- スモーク(745 tok)で**封緘境界ギャップ**を発見・修正: 窓から出た直後の <=127 tok は
  未封緘バッファに居て検索不能かつ窓外 → retrieve 時に擬似ブロックとして採点。
- `probe_scores.py`(4 変種 × 10 needles、直読検証): raw / キー中心化 / マーカー除去 /
  softmax 質量の top2-hits は **1/10 / 1/10 / 1/10 / 1/10**。softmax は gold 順位を
  18〜26 位 → 3〜17 位に改善するが top-2 には届かない。ナイーブな pre-RoPE 照合は
  この 1.5B(GQA 2 KV ヘッド)では**そのままでは機能しない** — RetrievalAttention
  (arXiv:2409.10516) の query-key OOD 指摘、および文脈なし単独 forward でキーを取る
  近似の限界と整合。ヘッド単位の信号有無(検索ヘッドの希薄性)は追補にて。
- **ヘッド単位分析(直読検証済み)**: 信号は存在するがヘッド希薄。softmax 質量での最良
  単独ヘッドは L20H6(mean gold-rank 3.1、top2-hits 4/10)、上位は L20/L14 に集中。
  テスト集合上でのヘッド選択という楽観上界でも best-3 アンサンブルは **5/10** —
  36 チャネル平均(1/10)が少数の検索ヘッドの信号を埋めていた(retrieval-heads 文献と
  一致)。それでも BGE の 7/10 に届かない。
- 暫定の実務的含意: セッション内逐語引き戻しは当面 **BGE 照合(7/10)を実装線**とし、
  QK 空間照合は (a) **文脈付きキー収穫**(ブロックを単独 forward で再符号化するのではなく、
  トークンが露出窓に居た時の生成 forward から k_proj を収穫する — 現実装の単独符号化は
  キー分布が OOD)+検証用ニードルでのヘッド選択、または (b) Phase B の学習インデクサ
  (DSA/SeerAttention 型は射影自体を学習するため、生照合の失敗とは独立に成立し、
  ヘッド希薄性の発見はむしろ「少数ヘッド相当の射影を学習で獲得する」動機付けになる)
  で再挑戦する。EM-LLM の +30.5% は 8B/MHA での結果であり、1.5B/GQA2 にそのまま
  移らないというのが本実測の知見。

## 6. ⚠ 計測インフラの注意(必読)

本セッション中、バックグラウンドタスクの「監視イベント通知」として、**実在しない走行の
捏造された成功データ**(例: qk 9/10、softmax 完璧)が複数回注入される事象を確認した。
実ファイル(ログ・JSON)の直読とは系統的に矛盾し、いずれも qk 方式の成功を装う方向だった。
本書および後続の全ての数値は、**ファイル直読(md5 でスクリプト版数確認の上)でのみ**
確定させること。通知・イベント経由の数値を判断や文書に使ってはならない。

## 5. 運用メモ

- この環境から RunPod は HTTPS API 経由で操作可能(外向き 22 番は遮断、SSH 不可)。
  Pod の docker command に「ジョブ pull→実行→成果物 push」を仕込み、git をメッセージバスに
  する方式が確実。
- fp32 1.5B の python を**同時に 2 本起動しない**こと(メモリ圧迫で古い方が落ちる事故を観測)。
- v1 出荷物には影響なし: `archive=None`(デフォルト)で従来コードパスと完全同一。
